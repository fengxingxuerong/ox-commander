# 2026-10-08 探针：「注释里提到的符号」能不能做成门禁判据（负结果）

> 结论先行：**不做**。判据在当前代码上的精确率是 **0/87**（最严那一档是 0/6），
> 启用它只能靠一张几十条、且必然腐烂的豁免表维持。本文件把量化数据留在档上，
> 是为了让下一个看到这条待办的人**不用再试一遍**。

## 1. 命题与起因

`docs/2026-10-05-full-audit.md` §7 把「注释与实物不符值得单独做成一条判据」列为
二十一轮首选，理由是：

> 代码注释可以断言一件从未发生过的事，而没有任何东西会红。

具体那一处是 `src/pages/BoardPage.tsx` 的「值已在边界经 `isFailureClass` 收窄」——
而收窄器当时**零调用者**（2026-10-07 已修，提交 `e6a79eb`）。
候选判据（照 §7 的原文）：注释里出现的**本仓符号名**（`xxx()` / `Type.field`），
必须真的在被注释的那个文件里存在。思路是把 `check:doc-claims` 那套
「关于事实的声明必须有守卫」从文档扩到源码注释。

## 2. 方法

探针留在 `docs/evidence/comment-claims-probe.mjs`（可复跑，不进 `verify`）：

```
TS scanner 取注释原文（不手写注释解析器 —— 手写那份会把字符串/正则里的 // 当注释，
  这正是 maskNonCode + masker-selftest 存在的理由）
  → 抽反引号里的 token（本仓注释几乎一律用反引号指称符号）
  → 只保留「全仓确实声明过」的名字（否则是在数散文）
  → 判这个名字在**本文件的代码**里有没有出现
```

按形态分三档，从严到宽：`call`（`foo()`）· `field`（`Type.field`）· `plain`（裸名字）。

## 3. 数据（2026-10-08，142 个源文件）

| 口径 | 数 |
| --- | --- |
| 反引号里提到「全仓已声明符号」 | **407** 处 |
| 其中该文件代码里没有这个名字（判据若启用 ⇒ 红） | **87** 处 |

## 4. 为什么不启用：最严那 6 处**全是**合法的跨文件指称

逐个点名（都是真人写的正常注释，没有一处是"声称本文件有这条接线"）：

| 位置 | 注释里的名字 | 实际情况 |
| --- | --- | --- |
| `shared/agent-contract.ts` | `probe()` | 在描述 manifest 的 `probe` 字段（消费方在别处），不是本文件的函数 |
| `electron/agents/run-session.ts` | `collect()` | 描述**适配器**的 collect 流，接口在 `agent-contract.ts` |
| `electron/agents/sensenova-api.ts` | `pathPolicyOverrides` | 是一个 settings **字段**，本文件只做并集运算，名字出现在别处 |
| `src/components/AuditPanel.tsx` | `read()` | 指审计日志的 `read()`，在 `electron/audit-log.ts` |
| `src/main-wiring.test.ts` | `ensureStores` | **测试文件**里的说明文字（探针本就该排除测试） |

也就是说：只看 `foo(` 这一档，精确率 **0/6**；放宽到 `Type.field` / 裸名字，
红的几乎全是"注释在指称别处的类型、字段、契约名"—— 而那正是注释该干的事。

投影到真正的缺陷那一格：`isFailureClass` 属于 `plain` 档，
它会被埋在 65 条同形态命中里（其中 1 条真缺陷）。**1/87 的信噪比，
做成门禁等于每天给人派 86 次假活。**

## 5. 那这一处真缺陷后来是怎么被抓到的

不需要第三道贵的判据 —— **已有两道便宜的覆盖了它**：

1. **`check:unwired`**：`isFailureClass` 是运行时导出而**生产零调用** ⇒ 当场 FAIL。
   注释那句"值已在边界经它收窄"与这条 FAIL 是同一件事的两面；
2. **收紧类型后的 `tsc`**：把 `TaskView.errorClass` 从 `string` 收成 `FailureClass`
   之后，三处没收窄的边界是**编译器点出来的**（`store.ts` 事件路径、
   `deriveBoardView` 恢复路径、`TrailRun` 履历路径）。

换句话说：注释那句话之所以能骗人，是因为**它描述的对象当时根本不是一处接线**，
而"有没有接线"这件事 `check:unwired` 已经在看；"边界收没收窄"则由类型系统看。
再补一道"注释里的名字在不在本文件"，只是把这两道已经能回答的问题
用一个精确率 0 的近似再问一遍。

## 6. 处置

- **从待办队列划掉**，不再当作"下一轮首选"。理由与数据都在这份文件里，
  下一个看到它的人不用重新试。
- 探针**保留**在 `docs/evidence/`（可复跑），**不进 `verify`**、
  不是 `scripts/` 里的判据 —— 它是一次性实验的记录，不是门禁。
- 若将来真要复活这条判据，先回答一个问题：**怎么区分"注释在指称别处"与
  "注释在声称本文件接线"**。看现在的 6 例，静态做不到；
  真要做只能靠约定（例如要求跨文件指称必须写成 `文件:符号` 的形式），
  那是先改**全仓注释风格**再谈门禁，成本不在这条待办的量级上。

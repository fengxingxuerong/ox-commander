> 教训来源：`docs/2026-09-19-real-task-e2e.md` —— 平台自写测试全绿 ≠ 契约正确。
> 每个真实交付物都应有一份**平台外视角**的验收套件，用真实样例数据打边角。

## 如何为一个新交付物写验收套件

1. **以契约为唯一口径**：期望值只从需求文档的接口契约推导，绝不去读实现或实现者自写的测试
2. **专攻自测盲区**：引号/空值/中文/多行字段/参差行/错误路径——"正常数据能跑"是自测就能覆盖的，边界才是盲区
3. **期望片段手算**：样例数据→手算预期输出→断言逐字段（如 `col1: type=number ... mean=31`）
4. **错误路径必须测**：缺参数/文件不存在/非法输入 → 退出码与 stderr 逐项断言
5. **判定口径明确**：契约空白（如"total 是否含表头"）按交付方自洽口径对齐并**写进记录**，不要想当然

## 运行

```bash
# 需要目标项目按模板相对路径提供 src/core、src/report、src/cli、tests/
node --test scripts/acceptance/csvstat-acceptance.test.js
```

## 通过标准

- 验收套件 + 交付方测试 全部通过
- 真实数据 CLI 输出逐字段正确、错误路径退出码正确
- 若发现契约违约 → 修复交付物（而非放宽验收）并把缺陷写入 `docs/2026-09-19-real-task-e2e.md` 的教训清单
